# 隐私哨兵参赛路线

首轮建议从高校社团的公开通知与活动招募文案切入。运营者经常从表格、聊天记录和模板复制报名信息，手机号可能被换行或排版字符拆开。发布者在浏览器里收到一条可解释的提示，确认后直接脱敏原文。第一轮试用可只覆盖招募帖和公开通知两个任务。

## 同类工作与差异假设

| 公开方案 | 已有能力 | 可比较的维度 |
|---|---|---|
| [Nightfall](https://www.nightfall.ai/lp/chatgpt-dlp) | 浏览器扩展实时扫描并脱敏 ChatGPT 提示词 | 普通网页编辑区的中文文案、提示与写回流程 |
| [Presidio](https://microsoft.github.io/presidio/) | 可扩展的个人信息识别与脱敏工具，支持文本和图像 | 在相同中文实体标注下比较识别质量，公开双方配置 |
| [Casper 论文](https://arxiv.org/abs/2408.07004) | 浏览器扩展在用户设备上清理发给网页大模型的提示词 | 中文号码排版变形、位置回映射与发布前交互 |

参赛主张应由数据支撑。可验证的假设是，给高校社团提供端侧提醒与原位脱敏，可以减少公开文案中的误发，又能把正常发布时的打扰控制在可接受范围。遇到更相似的项目，用同一批输入对照效果，记录运行配置和误判案例。公开说明借鉴之处，保留第三方许可，并将方案差异写成实验问题。

## 从规则走向端侧语义识别

当前回归集的 9 个拆分正例，旧引擎命中 0 个，更新后命中 9 个，脱敏均保留周边正文。这个结果描述的是已知漏洞样例。复跑命令为 `npm run test:privacy`。

1. 以当前规则为基线。手机号和银行卡等结构化字段继续用规则和校验位处理，现有位置映射用于脱敏与评分。用合成样本覆盖全角、零宽、换行、制表符和点号分组，同时覆盖 IP、版本号、小数和无敏感信息文案。
2. 用 Web Worker 试运行一个许可明确的轻量中文实体识别模型，优先补姓名、住址。通过 ONNX Runtime Web 或 Transformers.js 执行量化模型，测试 WebGPU 与 WASM。模型输出的位置转换为前端使用的 UTF-16 原文区间，与规则命中融合。首次加载与推理分开测量，模型加载失败时保留规则检测。用浏览器网络记录验证原文是否留在设备内。技术参考见 [ONNX Runtime Web](https://onnxruntime.ai/docs/get-started/with-javascript/web.html) 和 [Transformers.js 的 WebGPU 指南](https://huggingface.co/docs/transformers.js/main/guides/webgpu)。
3. 在固定测试集上比较原版规则、改进规则、规则加模型。按字段类型统计精确率和召回率，要求实体类别与原文区间同时正确。单独报告正常文案的误报率、脱敏后是否仍有完整敏感值、模型下载体积、首次加载时间和普通笔记本的 P95 延迟。用不同模板生成开发集和测试集，保留失败样本供复跑。

## 验证是否有人愿意用

先找两个社团的小规模志愿者，每组用虚构样例完成一次有守卫和一次无守卫的发布任务，交替安排顺序。观察能否发现并改掉敏感信息、任务时间和提示是否被接受。一周后询问参与者是否仍愿意开启守卫及原因。在授权范围内只汇总计数和反馈，样例采用合成内容。答辩时展示实际完成试用的人数、任务结果和误报实例。
