## 三、提交前必查清单（分四类）

> 等级说明：**必须修改** = 不改会导致出局、记 0 分或材料被拒；**建议优化** = 不影响提交，但直接影响得分。

### A. 参赛资格（出问题直接出局）

| 检查点 | 等级 | 怎么自查 | 补救措施 |
|---|---|---|---|
| 学生成员 ≤3 人（含队长） | 必须修改 | 报名表名单 vs 实际贡献者 | 拆分队伍或调整署名；注意"同一学生只能参加一队" |
| 指导教师为队长所属高校的**正式教师** | 必须修改 | 教师在职单位与队长学校是否一致 | 更换为符合条件的教师；跨校组队时按队长学校认定 |
| 无重复报名（同一学生未出现在两队） | 必须修改 | 逐队核对名单 | 退出其一 |
| 非主办/关联公司雇员及其直系亲属 | 必须修改 | 自查成员及亲属 | 此项无补救空间，属资格硬排除 |

### B. 作品技术合规（最常见的技术性驳回原因）

| 检查点 | 等级 | 怎么自查 | 补救措施 |
|---|---|---|---|
| **目标 HarmonyOS 版本达标**（创新赛要求 6.0+） | 必须修改 | 看 `build-profile.json5` 的 `compatibleSdkVersion` / `targetSdkVersion` | 升级 SDK 重新编译；低版本在创新赛直接记 0 分 |
| 未使用受限权限而未走 ACL 申请 | 必须修改 | 查 `module.json5` 的 `requestPermissions`，比对受限权限清单 | 走 ACL 申请流程，或改设计绕开该权限 |
| 每个权限都有明确用途说明 + 使用场景 | 必须修改 | 同上，看是否填了 `reason` 与 `usedScene` | 补齐字段；弹窗文案要和声明一致 |
| **应用内有可访问的隐私声明** | 必须修改 | 打开应用，看能否找到隐私政策入口 | 增加隐私政策页并在首次启动时展示 |
| 第三方库 License 已声明，无 GPL 传染风险 | 必须修改 | `oh-package.json5` 依赖清单 + 各库 LICENSE | 替换协议不兼容的库；在文档和源码中列明依赖与协议 |
| **HAP 为发布签名，非调试签名** | 必须修改 | 用签名工具查看证书信息 | 用发布证书 + Profile 重新打包；调试签名的包评委可能装不上 |
| 核心功能经过真机验证 | 建议优化 | 涉及蓝牙、星闪、NFC、摄像头、端侧 AI 的部分 | 模拟器对这些能力有明确限制，必须真机跑通 |

### C. 提交材料清单（缺项直接扣"材料分"甚至拒收）

| 检查点 | 等级 | 说明 | 补救措施 |
|---|---|---|---|
| 完整可编译源码 | 必须修改 | 含依赖清单与构建脚本，评审要能跑起来 | 清理临时文件后打包；附一份 README 说明构建步骤 |
| 安装包（签名的 HAP / App Pack） | 必须修改 | 部分赛项明确写"签名的 HAP" | 见 B 类签名项 |
| 作品说明文档 | 必须修改 | **必须用官网最新模板**，模板会更新 | 重新下载填写，不要沿用旧版 |
| 演示视频时长符合要求 | 必须修改 | 各赛不同：1-3 分钟 / 5 分钟 / 10 分钟 | 按你所在赛事的具体上限剪辑 |
| 视频需展示安装过程 + 核心功能 + 创新点 | 建议优化 | 部分赛项明确列出 | 补录安装与核心链路 |
| 视频需参赛者出镜（创新赛极客赛道） | 视赛事 | 1-3 分钟出镜介绍 | 补拍出镜片段 |
| 设计文档 / 用户手册 / 测试报告 | 视赛事 | 信创类赛项列为必交 | 按该赛项要求补齐，含界面截图与操作步骤 |

### D. 内容与评分（决定名次，不影响提交）

| 检查点 | 等级 | 依据 | 补救措施 |
|---|---|---|---|
| 应用类集成 ≥3 个鸿蒙特性 | 建议优化 | 官方"鼓励/建议集成 3 个及以上鸿蒙特性" | 补一个分布式、元服务或 AI 能力集成点 |
| **操作系统方向需有量化优化证据** | 必须修改 | 该方向的评审核心是"提升系统运行效率/协同能力/感知精度" | 给出优化前后的对比数据，并保留可复现的测试脚本与参数 |
| 有性能基线与复现方法 | 建议优化 | 官方答疑明确提到要保留测试脚本、参数配置与多轮结果 | 补一份可复现的测试说明 |
| 核心链路闭环优先于功能堆砌 | 建议优化 | 官方答疑强调 MVP 取舍：关键 Demo 崩溃比功能少更致命 | 砍掉不稳定功能，保主流程 |
