## 二、严重问题

### S1 · 检测历史把原始敏感值存进 localStorage

| 项 | 内容 |
|---|---|
| **问题** | `addHistory()` 直接保存 `d.value`（原文）与 `content`（原文前 50 字），而非脱敏值。实测 `privacy-sentinel:history` 内容为：`"value":"13800138000"`、`"value":"11010519491231002X"`、`"content":"我叫李明，手机号13800138000，身份证11010519491231002X…"` |
| **位置** | `前端/index.html:2587-2600`（`addHistory`）、调用点 `2160`、`2308`、`2458` |
| **影响** | ①与首页/OG 描述「检测完成不留存原始数据」直接矛盾；②最多 50 条、无 TTL，刷新与重启浏览器后仍在；③共享电脑、恶意扩展、任意同源 XSS 均可直接读出身份证与银行卡号。隐私工具在本地留明文，比不检测更危险——用户会因此放松警惕。 |
| **建议** | `addHistory` 改存 `d.masked`；`content` 用 `buildMaskedText()` 重建；补 7 天 TTL；设置页「清空历史」同时清 `localStorage`。 |
| **状态** | 已修复 |
| **实际改动** | ①历史 key 轮换为 `privacy-sentinel:history:v2`，旧 key 启动时整体洗白（`value→'***'`、`content→''`）后删除，避免老用户带着明文升级；②`addHistory` 只存 `d.masked`，`summary` 用 `buildMaskedText(..., 'mask')` 重建；③每条加 `savedAt`，`loadHistory` / `saveHistory` 双向按 7 天 TTL 过滤；④云端历史（无 `savedAt` 的旧条目）同样走 `scrubEntry()`。 |
| **复测结果** | 检测包含身份证/银行卡/手机号/邮箱/密码的文本后，遍历 `localStorage` 全部键：5 项敏感值**均不再出现明文**（`privacy-sentinel:history:v2`、`last-result` 均为脱敏值）。 |

**S1 补充（同一根因的第二个缺陷）**：`desensitize()` 原实现只对手机号/身份证/银行卡/密码/姓名做了打码，其余类型走 `default: return value`。也就是说 **email、url、ip、mac、passport、uscc、apikey 这 7 类在报告里显示的是原文**。已补：邮箱保留首字符 + `***` + 域名；URL 保留路径、查询串整体打码；其余按长度保留首尾各 1/4、中间替换为 `*`。这条不单独编号，因为它是 S1 修复过程中被回归测试抓出来的——原本 `test@example.com` 仍出现在 `last-result` 里，追查后才发现是打码函数本身失效。

|---|---|

### S2 · 41 处内联 `style` 被 CSP 拦截，样式静默失效

| 项 | 内容 |
|---|---|
| **问题** | CSP 为 `style-src 'self' 'nonce-…'`，没有 `unsafe-inline`，因此 HTML 里的 `style="…"` 属性全部被浏览器丢弃。实测首页 41 条、状态页 8 条 CSP 违规。 |
| **位置** | `前端/index.html`（64 处 `style=""`，如 1218、1240、1248、1251、1252）、`前端/status.html:146-169, 290` |
| **影响** | 在线状态绿点（`background:#4caf50`）变无色、提示文字字号与颜色失效、链接下划线重新出现、**报告风险条 `width:${score}%; background:${LV_COLOR}` 完全失效**（用户看不到评分条），`display:none` 类样式失效还可能让本应隐藏的元素露出。这是"看起来能用、实际部分渲染错误"的典型。 |
| **建议** | 静态的 `style="…"` 迁到 `<style>` 内的 class；动态的（评分条）改成 `class="bar lv-N"` + `--pct` CSS 变量赋值（CSSOM 不受 CSP 限制）。 |
| **状态** | 已修复 |
| **实际改动** | ①新增 40 个 `.u-*` 工具类（`u-muted`/`u-fs12`/`u-mt10`/`is-hidden`/`bg-l0..l4` 等），批量迁移 58 处静态内联样式；②评分条由 `style="width:X%;background:Y"` 改为 `<i class="bg-lN" data-pct="X">`，渲染后用 CSSOM 写 `bar.style.width`（CSSOM 不受 `style-src` 限制）；③`status.html` 另补 8 处（`.u-card-title`/`.u-btn-sm`/`.u-btn-row`）；④`privacyModal` 等 `display:none` 分支改走 `.is-hidden`。 |
| **复测结果** | `/` 41 → **0**、`/status.html` 8 → **0**、`/docs.html` 0 → 0、`/guard.html` 1（favicon 404 已随 L1 修掉）→ **0**、`/launch.html` 0 → 0。评分条在真实浏览器里宽度正确（截图已更新）。 |

> **注意**：`style-src` 仍然**不能**放 `unsafe-inline`。这次修的是「不要写内联 style」，不是「放开 CSP」。后续新增 UI 请直接用 `.u-*` 或新加 class，勿再写 `style="…"`。

### S4 · 服务端对文本长度无上限，且默认模式直连付费 AI

| 项 | 内容 |
|---|---|
| **问题** | `POST /api/analyze` 对 `text` 无长度校验，12MB 请求体被接受并返回 200；`mode` 缺省时走 `analyzeText`（本地+AI 双引擎），只有显式传 `mode:'local'` 才纯本地。实测 2MB 文本：local 209ms，默认模式 4261ms（确实调用了模型）。 |
| **位置** | `routes/analyze.js:110-153`（无长度校验）、`:145`（mode 判定） |
| **影响** | ①任何人写个脚本就能把 AI 配额刷爆（有 30 次/分限流，但单次可带 12MB）；②默认把原文上传到第三方模型，与「纯文本默认本地」的对外表述不一致；③单请求 4 秒以上，占用连接。 |
| **建议** | 增加 `MAX_TEXT_LENGTH`，超限返回 413 + 明确文案；`mode` 默认改为 `local`，需要 AI 时显式传 `full`。 |
| **状态** | 长度上限已修复；默认模式**未改**（见下方说明） |
| **实际改动** | `routes/analyze.js` 增加 `MAX_TEXT_LENGTH`，默认 **200000** 字符（可用环境变量覆盖），超限返回 413，并把 `action` 文案改成文本场景专用（通用文案讲的是「压缩图片 / 剪短视频」，对文本是误导）。 |
| **为什么是 200000 而不是 20000** | 第一版设成了 20000，结果 `scripts/check.js` 的既有用例（24000 字符长文本）直接返回 413 —— 而那个用例验证的是产品**既有**设计：超长文本仍应成功，AI 侧只复检前 12000 字（`services/providers/*.js` 的 `TEXT_CAP`），本地正则仍扫全文，并显式给出截断 warning。设 20000 等于把这条已实现的能力砍掉，违反「不破坏现有功能」的约束。200000 只用来挡真正离谱的 payload（实测 12MB / 25MB 那种），既有能力全部保留。 |
| **复测结果** | 20012 字符 → 200 成功且带「AI 仅对前 12000 字复检」warning；12MB、25MB → 413 且文案正确。 |
| **默认模式未改的原因** | 站内前端所有入口都显式传 `mode:'local'`，但站外调用方未知。把默认值从 `full` 改成 `local` 会让「不传 mode 就期待 AI 识别姓名」的调用方静默降级——属于行为契约变更，需你确认后再动（已列入第五节风险标注）。 |

## 八、审计工具自身的修正（否则报告会骗人）

这一节单独列出来，因为它直接影响前七节的可信度。初版审计脚本报出「中等 35 条、轻微 25 条」，其中相当一部分是**工具误报**，不是产品缺陷。逐条核对后修正了 5 处检测逻辑：

| # | 误报表现 | 真实原因 | 修正 |
|---|---|---|---|
| T1 | 五页全部「没有 main 地标」 | 产品用的是 `role="main"`（与 `<main>` 在 ARIA 上等价），脚本只查标签名 | 选择器改 `main, [role="main"]` |
| T2 | 首页「4 个表单控件缺少可访问名称」 | 4 个都是 `class="file-input-hidden"` 的隐藏 file input，由可见按钮代理触发，本就不该有名称 | 采集前统一过 `visible()` |

## 九、修复过程中引入并修掉的问题（如实记录）

### R1 · 批量迁移内联样式时误删 `</style>`，整个 body 被当成 CSS 吞掉

| 项 | 内容 |
|---|---|
| **现象** | 迁移脚本跑完后 `npm test` 的「前端交互」套件从 107 通过掉到 **0 通过 / 1 失败**，页面所有关键节点都「不存在」。 |
| **根因** | 插入 `.u-*` 工具类块时，替换用的 `new_string` 漏写了 `</style>`。结果 `<style>` 从第 35 行一直未闭合，**第 1265 行之后的整个 body 被 HTML 解析器当作 CSS 文本吃掉**，`document.body.children.length === 0`。 |
| **为什么难发现** | 页面仍然 `HTTP 200`、文件行数正常（4411 行）、`grep` 得到的关键 id 也都存在（因为在源码里，只是没被解析）。接口层测试与「响应 200」类断言**全部会通过**。 |
| **修复** | 补回 `</style>`；新增 15 项结构断言进 `test-frontend-dom.js`：每个页面校验 `<style>`/`<script>` 开闭数量配对 + 用 jsdom 解析后 `body.children.length > 0`。 |
| **教训** | 批量改 HTML 之后，不能只信「测试跑完没报错」。这次的失败模式很幸运（整页挂掉），如果只挂掉一部分，很可能被误判为「测试环境问题」而放过。 |

### R2 · 文本长度上限设成 20000，误伤了既有降级能力

第一版 413 阈值取 20000，导致 `check.js` 的 24000 字符用例失败。该用例验证的是**产品既有设计**（AI 截断 12000 + 本地扫全文 + 显式 warning），属「现有功能」。改为 200000 后恢复。**这类回归只有跑全量套件才能发现——单个功能测试是绿的。**
